# 人工审批清单

人工审批的目标是验证 AI 成果与证据，而不是重新完成一遍 AI 的全部工作。任何一项关键检查为“否”时，应打回或记录明确的风险接受理由。

## 产品负责人审批

- [ ] 业务目标、目标用户和价值与运营原始输入一致。
- [ ] 范围与非目标清晰，没有 AI 自行增加的功能。
- [ ] 业务规则、异常流程和权限无关键缺口。
- [ ] 每条验收标准具体、可观察、可测试。
- [ ] 假设和待确认项已由有权人员确认。
- [ ] 风险、依赖和成功指标可以接受。

## 研发需求评审审批

- [ ] AI 引用了正确的 PRD 版本和系统资料。
- [ ] 可行性、依赖、数据、安全、性能、兼容和测试均被覆盖。
- [ ] 问题严重度和打回阶段合理。
- [ ] 阻塞问题为零，或已明确打回。
- [ ] 初步拆分覆盖全部 AC-ID，估算依据可理解。

## 技术方案审批

- [ ] 方案满足 PRD，没有扩大或缩小业务范围。
- [ ] 接口、数据模型、异常、权限和组件边界明确。
- [ ] 迁移、兼容、监控和回滚可执行。
- [ ] 高风险项有负责人、缓解方法和验证方式。
- [ ] 每个任务可独立实施验证，并关联 AC-ID。

## Code Review 审批

- [ ] Review AI 与编码 AI 的上下文和指令隔离。
- [ ] Review 使用完整差异及必要的上下文文件。
- [ ] 每个问题都有代码位置、场景、影响和严重度。
- [ ] Review 覆盖需求一致性、正确性、安全、性能、兼容和测试。
- [ ] S0-S2 问题清零；S3 建议有明确处置。
- [ ] 无发现时仍记录检查范围和残余风险。

## 测试放行审批

- [ ] 测试构建和环境版本明确。
- [ ] 每个 AC-ID 至少关联一个已执行 TC-ID。
- [ ] 正常、边界、异常、权限和关键回归场景均覆盖。
- [ ] 执行证据真实可访问，失败分类有依据。
- [ ] 无未处置的 S0/S1；S2 风险已有明确决策。
- [ ] 残余风险和不覆盖范围已向运营、产品和研发披露。

## 审批记录

```text
检查项例外：
风险接受及理由：
附加条件、负责人、截止时间：
审批人 / 时间：
```
