# 编码证据快照与下游传递设计

## 目标

让代码 Review、自动化测试和运营验收基于真实、可追溯的编码证据执行，而不是只读取编码阶段的文字总结。编码完成时生成不可变证据快照，下游阶段引用同一次 Execution 的 Git diff、文件清单、自测记录和诊断。

## 证据模型

新增 `coding_evidence`，与编码 Execution 一对一。保存：

- 证据 ID、Execution ID、需求 ID和项目 ID。
- AI 分支、worktree 路径和 Codex thread ID。
- Git diff SHA-256。
- 修改文件列表、文件数、增加行数和删除行数。
- Git diff 快照、原始字符数和是否截断。
- 自测命令、退出码、结果摘要和诊断。
- 创建时间。

证据创建后不可覆盖。重新执行编码会生成新的 Execution 和新证据。

## 快照生成

编码 Codex 结束并读取最终 Git diff 后，服务端在创建编码 Artifact 前生成证据快照。文件清单和增删行通过结构化 Git 命令读取，不从模型总结中解析。

Git diff 使用 SHA-256 计算稳定哈希。默认最多保存 120000 个字符；超过上限时保存前后片段并标记 `truncated=true`，同时保留完整文件清单、原始字符数和哈希。

编码 Artifact 增加 `evidenceId`、`evidenceExecutionId` 和 `evidenceDiffHash`。

## 下游证据选择

代码 Review、自动化测试和运营验收启动前，选择当前需求最新一次状态有效的编码证据。选择依据是编码 Execution 创建时间，而不是 Artifact 排序。

调用下游 AI 时附加：

- 证据元数据。
- 修改文件和增删行统计。
- Git diff 快照。
- 测试命令和结果。
- Codex 诊断。

下游 Artifact 同样记录使用的证据 ID、Execution ID 和 diff 哈希。

## 有效性检查

使用证据前读取 worktree 当前 diff 并重新计算哈希：

- 哈希一致：`valid`。
- 哈希不一致：`stale`，停止自动 AI 审核，进入人工判断。
- worktree 不存在：`unverifiable`，保留快照但进入人工判断。
- 没有证据：`missing`，停止自动 AI 审核，进入人工判断。
- diff 已截断：`truncated`，允许 AI 辅助分析，但门禁强制转人工。

证据状态不会修改历史快照。

## 阶段行为

代码 Review 必须有 `valid` 或 `truncated` 证据才调用 AI。自动化测试和运营验收遵循相同规则。

证据缺失、过期或无法验证时不调用模型，服务端创建一份确定性的阻塞 Artifact，说明原因、证据状态和恢复步骤，并通过门禁进入人工判断。

证据有效时，AI 必须在 facts 中引用证据 ID 和 diff 哈希。门禁在以下情况强制人工：

- 证据状态不是 `valid`。
- Git diff 被截断。
- 下游 Artifact 引用的证据与当前选择不一致。

## 界面

编码自测成果显示“编码证据”区域：证据状态、Execution ID、分支、diff 哈希、文件数、增删行、自测结果和截断状态。

代码 Review、自动化测试和运营验收显示“本次使用的编码证据”，提供 Git diff 展开入口。自动打回记录显示是代码风险还是证据不足触发。

状态文案：

- `有效`：快照和 worktree 一致。
- `已过期`：worktree diff 已变化，需要重新编码自测。
- `无法验证`：worktree 不存在。
- `已截断`：证据存在但 diff 未完整提供，必须人工。
- `缺失`：没有可用编码证据。

## 异常处理

- 证据生成失败时编码运行标记失败，不推进到代码 Review。
- 哈希或 Git 命令失败时降级人工，不允许自动通过。
- 大 diff 截断必须保留明确标记、原始字符数和完整文件清单。
- worktree 被删除后仍可查看历史快照，但不能自动审核。
- 旧编码 Execution 没有证据时按 `missing` 处理，不根据历史文字总结伪造证据。

## 测试与验收

单元测试覆盖哈希稳定性、diff 截断、文件统计、最新证据选择和状态计算。

Store 测试覆盖不可变快照、一 Execution 一证据和需求证据查询。API 测试覆盖证据详情、缺失/过期拦截和下游上下文包含真实 diff。

浏览器使用 `REQ-0005` 验收：重新执行编码生成证据，确认代码 Review 页面显示真实 diff，再运行 Review 并核对 Artifact 引用的证据 ID。验收不 push，也不修改点餐项目主工作区。

## 非目标

- 不自动提交、合并或 push 代码。
- 不从 AI 文字总结反向解析 Git diff。
- 不覆盖或修补历史证据。
- 不在证据无效时自动放行下游阶段。
