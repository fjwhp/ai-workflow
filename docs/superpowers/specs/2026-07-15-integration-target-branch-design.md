# 合并目标分支选择设计

## 问题

当前代码合并节点直接使用项目登记时保存的 `defaultBranch`。Soto Dine 首次登记时前端默认值被硬编码为 `prod`，因此 REQ-0005 显示目标分支为生产分支。项目当前实际分支是 `feature/0710-serious-msg`，预检因分支不一致而失败；界面又只在预检全部通过时渲染合并按钮，导致用户既看不到按钮，也无法纠正目标分支。

## 目标

- 目标分支按需求选择和保存，不再隐式等于项目默认分支。
- 首次进入待合并节点时默认选择项目主工作树当前分支。
- 合并按钮始终可见；条件不满足时禁用并显示原因。
- `prod`、`main`、`master` 等保护分支不能被误选后直接合并。

## 数据模型

在需求上新增可空字段 `integration_target_branch`。进入代码合并节点时：

1. 若需求已有目标分支，继续使用该值。
2. 若为空，服务端读取已登记项目主工作树当前分支并作为建议值返回。
3. 用户确认选择后通过专用接口保存到需求。

历史 Integration Run 继续保存当次实际 `target_branch`，不随需求后续选择变化。

## 分支查询与选择

服务端从已登记项目仓库读取本地分支：

- 使用参数数组执行 `git branch --format=%(refname:short)`。
- 只返回本地分支，不自动创建、切换或拉取分支。
- 返回当前分支、分支列表和保护状态。
- 客户端不能提交任意仓库路径，只能提交列表中的分支名。

新增接口：

- `GET /api/requirements/:id/integration-branches`：返回当前分支、本地分支列表、已选目标和保护状态。
- `PATCH /api/requirements/:id/integration-target`：校验需求处于代码合并节点、分支存在，然后保存目标分支。

## 预检与执行

预检和实际合并都使用需求保存的目标分支，不再使用 `project.defaultBranch`。必须同时满足：

- 主工作树当前分支等于需求目标分支。
- 目标工作树干净。
- 编码证据、AI worktree 和源分支有效。

每次实际合并前重新读取需求目标分支并再次预检，防止页面状态过期。

## 保护分支

默认保护分支名：`prod`、`production`、`main`、`master`。

- 普通确认弹窗不能提交保护分支合并。
- 选择保护分支时显示明确警告，并要求用户输入完整分支名进行二次确认。
- 后端要求请求包含与目标分支完全一致的 `protectedBranchConfirmation`，否则返回 409。
- 非保护分支不要求额外文本确认。

## 界面

代码合并面板展示目标分支下拉框：

- 默认选中当前本地分支，例如 `feature/0710-serious-msg`。
- 切换选择后保存并重新执行预检。
- 当前分支带“当前”标识，保护分支带“保护”标识。
- 合并按钮始终显示。预检失败时禁用，按钮下方列出失败原因。
- 目标分支未保存、正在检查或存在活动合并时按钮禁用。
- 确认弹窗显示最终目标分支，而不是“项目默认分支”。

REQ-0005 在首次加载新接口时建议并保存当前分支 `feature/0710-serious-msg`，不会修改项目全局 `defaultBranch=prod`。

## 测试

- Git：读取当前分支和本地分支列表。
- Store：保存和读取需求目标分支，旧数据库迁移兼容。
- API：分支不存在、错误阶段、保护分支确认缺失、普通分支成功。
- 预检：使用需求目标分支，当前分支匹配后通过。
- Web：按钮始终存在；失败时禁用；选择当前分支后重新预检；保护分支警告。
- 浏览器：REQ-0005 显示 `feature/0710-serious-msg`，但不执行真实合并。

## 非目标

- 不自动 checkout、pull、push 或创建分支。
- 不修改项目全局默认分支。
- 不在本次验收中合并 REQ-0005。
