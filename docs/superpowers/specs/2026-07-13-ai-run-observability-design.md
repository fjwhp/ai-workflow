# AI 阶段运行可观测性设计

## 目标

让工作流中每个阶段的 AI 运行都可实时查看、可追溯、可恢复。用户点击当前阶段的“AI 处理中”状态或历史阶段的运行入口，即可查看该次运行的实际脱敏输入、处理步骤、原始输出、最终结果和错误诊断。

本功能覆盖产品 PRD、需求评审、技术设计、编码自测、代码 Review、自动化测试和运营验收。编码阶段继续使用独立 Codex 会话，但其事件会映射到统一运行记录模型。

## 已确认的产品决策

- 使用弹窗展示执行详情，不在阶段成果区域内嵌长日志。
- 展示发送给 AI 的完整提示词和项目上下文，但在持久化前隐藏敏感值。
- 使用 SSE 推送实时事件，并使用 SQLite 持久化全部运行记录。
- 页面刷新或 SSE 重连不会中断后台 AI，客户端能恢复已有事件并继续接收。
- 当前运行和历史运行使用同一详情界面。

## 数据模型

复用现有 `stage_runs` 表作为每次阶段执行的主记录。每次用户确认启动 AI 后立即创建记录，再将需求状态切换为 `ai_running`。

`stage_runs` 保存：

- 需求 ID、工作流阶段和运行状态。
- 实际模型名称。
- 脱敏后的完整输入 JSON。
- 最终输出 JSON。
- 错误摘要。
- 创建时间与完成时间。

新增 `stage_run_events` 表，字段包括事件 ID、运行 ID、单调递增序号、事件类型、事件载荷 JSON 和创建时间。序号用于稳定排序和 SSE 断线续传。

统一事件类型包括：

- `run.started`：运行已创建。
- `context.prepared`：脱敏上下文已准备。
- `request.sent`：请求已发送到中转接口或 Codex 子进程。
- `output.delta`：收到增量输出。
- `step.started` / `step.completed`：阶段内处理步骤变化。
- `command.started` / `command.completed`：Codex 命令执行。
- `file.changed`：Codex 文件修改。
- `result.parsed`：结构化结果解析完成。
- `run.completed` / `run.failed`：运行结束。

编码运行现有的 thread ID、worktree、branch、Git diff 和 JSONL 事件仍保留在 `executions` 表，同时写入对应 `stage_run` 和标准化事件，避免破坏已有编码详情功能。

## 服务端流程

启动接口先进行并发保护：同一需求同一阶段存在 `running` 记录时拒绝重复启动。之后创建 `stage_run`，保存脱敏输入并返回运行 ID。AI 在后台继续执行，事件持续写入 SQLite 并广播给 SSE 订阅者。

普通阶段的 OpenAI 兼容请求启用流式响应。服务端逐块记录 `output.delta`，拼接完整响应，解析并校验结构化产物，最后创建不可覆盖的 Artifact。

编码阶段在启动 Codex、接收 JSONL、执行命令和产生文件变化时同步追加标准事件。编码仍只操作隔离 worktree，不自动提交、合并或推送。

提供以下读取接口：

- 获取某需求的运行列表，可按阶段筛选。
- 获取单次运行及全部历史事件。
- 订阅单次运行的 SSE 事件流，支持通过最后事件序号续传。

运行结束后，需求进入 `awaiting_approval`。运行失败时需求恢复为 `ai_ready`，对应运行标记为 `failed`，已接收事件和输出不会删除。

## 脱敏规则

所有输入、事件和输出在写入 SQLite 前经过同一递归脱敏器。脱敏器处理：

- `apiKey`、`authorization`、`cookie`、`token`、`secret`、`password` 等敏感键名。
- Bearer 凭据和常见 API Key 文本模式。
- `.env` 内容、私钥块以及项目 `sensitivePatterns` 命中的路径或内容。

脱敏值统一替换为 `[REDACTED]`。日志和 SSE 只读取已经脱敏的数据，不广播未持久化的原始敏感载荷。

## 前端交互

当前阶段处于 `ai_running` 时，状态胶囊可点击，并在操作区显示“查看执行”按钮。历史流程节点如果存在运行记录，也显示查看入口。

执行详情弹窗顶部展示阶段、模型、状态、开始时间和动态运行时长。主体包含四个页签：

1. `执行过程`：按时间展示标准事件，自动跟随最新事件，并允许暂停自动滚动。
2. `输入上下文`：展示完整脱敏提示词、需求、历史产物和项目上下文。
3. `原始输出`：普通阶段显示中转接口增量文本；编码阶段显示 Codex 分析、消息、命令和文件修改事件。
4. `最终结果`：完成后展示结构化产物；失败时展示错误阶段和诊断。

弹窗首次打开先读取 SQLite 中已有记录，再连接 SSE。断线自动重连并携带最后事件序号，避免重复或遗漏。运行完成后停止重连并刷新需求详情，使最终 Artifact 和审批入口同步出现。

## 异常处理

- 中转接口超时、连接中断或返回非法内容时记录 `run.failed`，保留已收到的输出。
- SSE 断开只影响实时展示，不取消后台运行。
- 结构化结果解析失败时原始输出仍可查看，需求恢复为可重新启动状态。
- 服务进程意外退出后，启动时将遗留的 `running` 记录标记为 `interrupted`，避免永久显示处理中。
- 前端无法获取运行详情时展示明确错误和重试命令，不用空白弹窗替代错误。

## 测试与验收

后端测试覆盖运行创建、同阶段并发保护、事件序号、持久化、脱敏、成功结束、失败保留输出、遗留运行恢复和 SSE 续传。

前端测试覆盖处理中状态可点击、运行入口按阶段匹配、四个页签、事件增量追加、断线恢复、历史运行查看和失败状态。

集成验收使用真实本地中转执行一个非编码阶段，在应用内浏览器确认弹窗实时更新、刷新恢复和最终产物切换。该验收不修改点餐项目源码。编码阶段另用隔离 worktree 验证 Codex 事件映射和 Git diff 展示。

## 非目标

- 不提供跨机器同步或多人协作。
- 不提供运行取消、暂停或人工修改 AI 原始输出。
- 不保存未脱敏的密钥或鉴权信息。
- 不改变现有人工审批、打回上一阶段和不可覆盖产物规则。
