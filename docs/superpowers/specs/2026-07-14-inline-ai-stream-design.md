# 阶段内嵌 AI 实时执行流设计

## 目标

AI 处理中，当前阶段页面直接展示类似 Codex 的实时执行流。只展示模型对用户可见的输出、工具操作、文件变化、测试和门禁结果，不展示内部推理内容。

## 页面结构

当前阶段状态为 `ai_running` 且存在活动 Stage Run 时，成果区域显示内嵌实时执行面板：

- 顶栏：阶段名称、运行状态、模型、开始时间、运行时长。
- 工具栏：停止执行、打开完整执行详情。
- 事件流：按事件序号从旧到新排列，最新处理位于底部。
- 底部状态：连接状态、最后事件时间和“回到最新”。

原有执行详情弹窗保留，作为完整输入、原始输出和最终结果的查看入口。

## 可见事件

前端只渲染以下事件：

- `run.started`：开始执行。
- `context.prepared`：上下文准备完成，只显示摘要和数量，不展开完整敏感上下文。
- `request.sent`：请求已发送。
- `output.delta`：模型对用户可见的增量文本，连续片段合并为一个流式消息。
- `codex.event` 中的命令执行、文件修改、代理消息和测试结果。
- `diagnostic`：可操作的诊断和错误，不展示推理草稿。
- `file.changed`：文件名、变化类型和增删行统计。
- `gate.decided`：自动通过、人工判断或打回及原因。
- `run.completed`、`run.failed`、`run.interrupted`：终态。

明确过滤 reasoning、内部分析、隐藏提示词和完整请求载荷。

## 流式行为

- 初次渲染先读取 Stage Run 快照和已持久化事件。
- 以最后一个事件序号连接 SSE，避免重复。
- 新事件按序号去重并追加。
- 连续 `output.delta` 合并到当前模型消息，减少闪动。
- 用户位于列表底部时自动跟随最新事件。
- 用户主动向上滚动超过阈值后暂停跟随，并显示“回到最新”。
- 点击“回到最新”恢复跟随。
- 命令输出、Git diff 和长诊断默认折叠；当前运行事件默认展开。
- 使用稳定高度和最小尺寸，避免事件追加导致操作区跳动。

## 刷新与断线

- Stage Run 事件继续以 SQLite 为事实来源。
- 页面刷新后重新读取快照，再从最后序号恢复 SSE。
- SSE 中断显示“连接中断，正在重连”，保留已有内容。
- 浏览器原生 EventSource 自动重连；重连后按序号去重。
- 收到终态事件后关闭 SSE、刷新需求详情并保留完整执行流。
- 没有活动 Run 但需求仍是 `ai_running` 时显示恢复提示，不伪造运行内容。

## 停止执行

本期工具栏展示“停止执行”入口，但只有后端支持可取消运行时才启用。若当前执行器不可取消，按钮禁用并说明“当前执行器暂不支持主动停止”，避免提供无效操作。

## 组件边界

- `stream-view.ts`：纯函数，过滤、归一化、合并事件并生成展示模型。
- `InlineRunStream`：负责快照、SSE、自动跟随和终态刷新。
- 现有 `RunDetailsModal`：继续负责输入、原始输出和完整结果。
- 现有 Stage Run API 与事件表不改变协议。

## 可访问性与响应式

- 事件状态不只依赖颜色，同时显示文字和图标。
- 实时区域使用 `aria-live="polite"`，避免每个增量字符打断读屏。
- 手机宽度下工具栏换行，命令和路径允许断行。
- 实时区域最大高度基于视口，内部滚动，不把审批操作推到页面底部。

## 测试

- 纯函数：过滤 reasoning、增量合并、事件去重、终态识别和倒序输入纠正。
- 组件行为：快照恢复、SSE 追加、断线提示、终态刷新和自动跟随暂停。
- 浏览器：桌面与手机宽度验证实时流不遮挡、不溢出、操作面板位置稳定。
- 回归：完整执行详情弹窗、现有 Artifact、审批和门禁展示保持可用。

## 非目标

- 不展示内部推理或隐藏提示词。
- 不改变模型、中转接口或 AI 调用协议。
- 不将未持久化的临时浏览器状态作为执行事实。
