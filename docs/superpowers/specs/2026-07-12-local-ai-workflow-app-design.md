# 本地 AI 研发工作流应用设计

## 1. 目标与边界

构建一个可长期维护的本地全栈 Web 应用，把现有 AI 研发 SOP、表单和审批清单转化为可操作界面。应用在本机保存业务数据，通过 OpenAI API 执行产品、研发、编码、Review 和测试任务，并允许编码 AI 在隔离 Git worktree 中修改已登记项目和运行白名单命令。

第一版面向单用户，仅监听 `127.0.0.1`，不提供登录、局域网访问、生产发布或多人协作。架构需允许未来迁移到 PostgreSQL、远程 Worker 和团队权限体系。

## 2. 核心交互

主界面采用“工作台优先”布局：顶部提供工作台、需求、项目、运行记录和设置；左侧显示待人工审批、AI 待启动、AI 执行中、已阻塞和已完成队列；主区域展示需求及阶段详情。

需求详情以阶段时间线组织运营提需、PRD、需求评审、技术设计、编码自测、Code Review、测试和运营验收。审批页默认展示 AI 结论、置信度、问题、风险和证据，完整产物按需展开。人工可以批准、条件批准或打回。

AI 不自动启动。用户点击运行后，应用先展示模型、任务和将发送给 OpenAI 的全部上下文，允许排除文件，确认后才调用 API。人工批准只解锁下一阶段。

## 3. 技术架构

- 前端：React、TypeScript、Vite。
- 后端：Node.js、TypeScript、Fastify。
- 数据：SQLite、Drizzle ORM，数据库与附件位于本地 `data/` 目录。
- 通信：REST 处理常规操作，SSE 推送 AI 输出和命令日志。
- AI：OpenAI Responses API；模型从环境变量读取，AI 输出经共享 Schema 校验。
- 执行器：使用 Git worktree 隔离代码变更，以参数数组运行允许命令。
- 代码结构：`web`、`server`、`shared` 分离，前后端共享领域类型与校验 Schema。

`OPENAI_API_KEY` 仅从本机环境读取。默认模型通过 `OPENAI_MODEL` 配置，编码模型另设配置项，避免将模型 ID 固化到业务代码。

## 4. 领域模型

- `Project`：仓库路径、默认分支、命令白名单、敏感文件规则和上下文设置。
- `Requirement`：需求编号、标题、优先级、当前阶段和状态。
- `StageRun`：阶段的一次 AI 运行及输入版本、模型、状态、用量和错误。
- `Artifact`：PRD、评审、设计、自测、Review、测试和验收的不可变版本。
- `Finding`：问题、严重度、证据、建议和目标责任阶段。
- `Approval`：批准、条件批准或打回决定及理由。
- `TraceLink`：AC、任务、提交、测试和缺陷之间的追溯关系。
- `AgentProfile`：AI 角色、提示词版本、模型和结构化输出类型。
- `Execution`：worktree、分支、Git 操作、命令、退出码和日志。
- `Attachment`：本地附件元数据和校验信息。

所有记录使用稳定 ID、创建时间和版本号。Artifact 不覆盖更新，重新运行产生新版本；需求关闭后只读，必须显式重新打开。

## 5. 工作流

统一状态为：

`草稿 -> AI 待启动 -> AI 处理中 -> 待人工审批 -> 已批准/已打回/已阻塞 -> 下一阶段`

新建需求后生成 `REQ-ID`。AI 输出校验通过后生成 Artifact；批准解锁下一阶段；条件批准必须填写条件、负责人和截止时间；打回必须填写目标阶段、严重度、理由和重新提交条件。

编码 AI 和 Review AI 使用独立运行上下文。编码阶段创建独立 worktree 和功能分支；Review 阶段只接收批准的需求、设计、完整代码差异、相关文件和自测证据，不继承编码 AI 的运行上下文。

## 6. 本地代码执行

- 项目必须由用户显式登记并验证为 Git 仓库。
- 默认分支不可直接修改，每次编码运行创建独立 worktree。
- 项目设置包含允许命令及固定参数；清单内自动执行，清单外请求人工确认。
- 禁止强制推送、硬重置、任意目录删除和未经确认的提交、合并、推送。
- 命令不经 Shell 字符串拼接，运行目录限制在对应 worktree。
- 文件差异、命令、退出码和日志实时显示并持久化。
- `soto-dine` 初始允许命令包括针对指定 Maven 模块的测试、构建和静态检查，不默认允许全仓库发布命令。

## 7. 安全与隐私

- API Key 不进入数据库、日志、前端响应、备份或项目文件。
- 服务仅绑定回环地址；第一版不开放远程访问。
- AI 只能访问登记仓库和本次 worktree。
- 项目敏感规则默认排除 `.env`、密钥、证书、凭据、构建产物和 Git 内部文件。
- 每次 AI 运行前显示上下文预览，并允许用户排除材料。
- 应用启动时检查数据与附件目录权限。

## 8. 失败恢复与备份

- OpenAI 超时、限流或格式错误保存尝试记录并允许重试；重试不重复生成 Artifact。
- 应用重启后恢复任务状态；无法恢复的外部进程标记为已中断。
- 命令失败保存退出码和日志，并进入 AI 分析或人工处理。
- worktree 创建失败、仓库状态不满足要求或默认分支不明确时停止执行。
- SQLite 写入使用事务和外键；附件采用临时文件加原子移动。
- 支持一键备份和恢复 SQLite、附件、提示词版本、Agent 配置及项目设置；恢复前校验清单和文件哈希。

## 9. 验收标准

- 用户能登记 `soto-dine` 路径、默认分支、敏感规则和 Maven 白名单命令。
- 能创建 `REQ-DINE-001` 并走完全部阶段，查看完整版本与审批历史。
- 产品、研发、编码、Review 和测试 AI 能独立运行并生成通过 Schema 校验的成果。
- 人工能批准、条件批准和打回，并强制填写对应必要信息。
- 编码 AI 只能在隔离 worktree 中修改代码和执行允许命令。
- UI 实时展示 AI 输出、Git 差异和命令日志。
- API、命令和进程失败不破坏已保存数据，应用重启后状态明确。
- 备份可以恢复需求、产物、审批、提示词和项目设置。
- 桌面和手机窄屏下文字、阶段栏、表单和操作控件不重叠。

## 10. 第一版非目标

- 多用户登录、角色权限和审计合规平台。
- 局域网或公网部署。
- 自动提交、合并、推送或生产发布。
- 任意 Shell 命令执行。
- 向量检索、跨项目知识库和自动长期记忆。
- 除 OpenAI 之外的模型供应商适配。
